无八股无手撕，整体面试氛围比较轻松，面试官人很好，能明显感受到交流感，交流过程更像围绕项目进行深入讨论，不是单纯按照固定题库提问。很多问题会根据上一道回答继续追问，所以需要真正理解自己项目中的设计，而不是只背准备好的答案。

面试开始后，先让我介绍了一个自己比较熟悉的项目。后续问题主要围绕项目中的 Agent 架构展开，大致包括：

项目中的 Agent 整体是如何设计和划分的？

用户提出一个问题后，系统内部会经过怎样的完整处理流程？

项目中包含哪些 Agent？每个 Agent 分别负责什么？

多个 Agent 之间如何进行任务分配、路由和协作？

Memory 机制是如何设计的？保存了哪些信息？

为什么要这样设计 Memory？不同类型的记忆分别解决什么问题？

如何避免历史信息过多导致上下文污染或 Token 消耗过大？

Agent 的评审或评价机制是如何设计的？

如何判断 Agent 给出的回答是否准确、完整和安全？

Memory 如何与多 Agent 架构结合？

当 Agent 回答失败、置信度不足或出现异常时，系统如何处理？

项目中的关键设计为什么选择这种方案？是否考虑过其他实现方式？

每道题的范围都比较大。即使最开始只是几句话的问题，面试官也会根据回答继续追问很多细节，例如具体实现方式、模块职责、设计原因、异常处理以及不同模块之间如何配合。

个人感受是，这场面试比较重视项目深度。准备时不仅要知道“项目用了什么”，如果项目是自己完整做过的，并且提前梳理好架构、流程和常见追问，整体交流会比较顺畅。面试官也会根据回答给出一些比较实用的建议，整体体验给到夯。
